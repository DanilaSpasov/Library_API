# Library API

**Library API** — backend-сервис для управления физической библиотекой.
Проект хранит каталог книг и отдельных экземпляров, оформляет выдачи и возвраты,
уведомляет читателей о появлении книги и предоставляет Telegram-бота с
AI-помощником.

---

# Технологии и стек

* **Язык программирования:** Python 3.14
* **Фреймворк:** Django 6.1
* **REST API:** Django REST Framework
* **Аутентификация:** JWT, Simple JWT
* **Документация API:** drf-spectacular, Swagger UI
* **СУБД:** PostgreSQL
* **Брокер сообщений:** Redis
* **Фоновые задачи:** Celery
* **Telegram:** Telegram Bot API через HTTP-запросы
* **AI-помощник:** OpenRouter API
* **Менеджер зависимостей:** Poetry
* **Production-сервер:** Gunicorn
* **Reverse proxy:** Nginx
* **Контейнеризация:** Docker, Docker Compose
* **CI/CD:** GitHub Actions
* **Контроль версий:** Git / GitHub

---

# Структура проекта

Проект состоит из трёх Django-приложений:

* **users** — пользователи, роли, регистрация, подтверждение email,
  JWT-аутентификация и одноразовые коды привязки Telegram;
* **library** — авторы, жанры, книги, физические экземпляры, выдачи, возвраты,
  подписки и email-уведомления;
* **telegram_bot** — меню бота, поиск по каталогу, работа с личными данными
  читателя и запросы к OpenRouter.

Общие настройки Django, маршруты и конфигурация Celery находятся в каталоге
`config`.

# Функциональность

## Пользователи и роли

Вход выполняется по email, поле `username` не используется. Новый читатель
регистрируется через API, получает письмо со ссылкой и после подтверждения email
может получить JWT-токены.

В проекте предусмотрены три роли:

* **читатель** просматривает каталог и свои выдачи, создаёт и удаляет собственные
  подписки на недоступные книги;
* **библиотекарь** управляет каталогом и экземплярами, оформляет выдачи и
  возвраты, просматривает выдачи всех читателей;
* **администратор** обладает правами библиотекаря, может менять активность книг
  и управлять данными через Django Admin.

## Каталог

Каталог содержит авторов, жанры, книги и отдельные физические экземпляры.
У экземпляра есть уникальный инвентарный номер и состояние: доступен, выдан,
повреждён, находится на ремонте, утерян или списан.

Поддерживаются:

* поиск книг по названию, ISBN, автору и жанру;
* фильтрация по автору, жанру и наличию доступного экземпляра;
* сортировка книг, авторов, жанров и экземпляров;
* пагинация по 10 элементов с возможностью указать `page_size` до 50;
* скрытие неактивных книг от обычного читателя;
* подсчёт доступных экземпляров для каждой книги.

Физическое удаление книг через API не используется: исключённую из каталога
книгу администратор помечает неактивной.

## Выдача и возврат книг

Выдачу и возврат оформляет библиотекарь или администратор по инвентарному
номеру экземпляра.

При выдаче система проверяет, что:

* пользователь является активным читателем с подтверждённым email;
* экземпляр найден, доступен и относится к активной книге;
* у читателя нет просроченных книг;
* у читателя меньше трёх активных выдач.

Срок возврата автоматически устанавливается на 14 дней. При возврате экземпляр
можно отметить доступным или повреждённым. Читатель видит только собственные
выдачи, а сотрудники — все выдачи. Доступна фильтрация по активным, возвращённым
и просроченным выдачам.

## Подписки и email-уведомления

Если у книги нет доступных экземпляров, читатель может подписаться на её
появление. Когда экземпляр снова получает состояние «Доступен», Celery ставит в
очередь отправку email всем ожидающим читателям. После успешной отправки
подписка отмечается обработанной, поэтому повторное письмо по ней не приходит.

## Telegram-бот

Бот работает через Telegram Bot API в режиме long polling.

В меню доступны кнопки:

* `📚 Книги` — первые десять активных книг;
* `🔎 Поиск` — поиск по названию, автору или ISBN;
* `⭐ Мои подписки` — просмотр и удаление активных подписок;
* `📖 Мои выдачи` — просмотр книг и сроков возврата;
* `🔗 Привязать аккаунт` — инструкция по подключению аккаунта;
* `ℹ️ Помощь` — краткая справка.

Для просмотра личных выдач и подписок Telegram необходимо привязать к аккаунту:

1. Авторизоваться в Library API.
2. Получить одноразовый код запросом
   `POST /api/auth/telegram/connection-code/`.
3. В течение 10 минут отправить боту `/connect КОД`.

После привязки бот находит пользователя по Telegram `chat_id`. Код хранится в
виде хеша, действует один раз и удаляется после успешного использования.

## AI-помощник

Обычный текст, который не является командой или ответом на поиск, передаётся в
OpenRouter. AI определяет намерение пользователя: найти книгу, показать каталог,
подписки или выдачи либо дать обычный справочный ответ. Поиск и личные действия
выполняются по данным проекта, а не по выдуманному AI каталогу.

По умолчанию используется маршрутизатор `openrouter/free`. Бесплатные модели
имеют ограничения по числу запросов и иногда могут быть временно недоступны.
При ошибке AI основные кнопки Telegram-бота продолжают работать.

# Переменные окружения

Создайте `.env` на основе файла `.env_example`:

```
cp .env_example .env
```

В `.env` указываются:

* `SECRET_KEY` — секретный ключ Django;
* `DEBUG` — режим отладки, на сервере должен быть `False`;
* `ALLOWED_HOSTS` — разрешённые адреса через запятую;
* `CSRF_TRUSTED_ORIGINS` — доверенные адреса с `http://` или `https://`;
* `DATABASE_NAME`, `DATABASE_USER`, `DATABASE_PASSWORD` — данные PostgreSQL;
* `DATABASE_HOST`, `DATABASE_PORT` — адрес и порт PostgreSQL;
* `EMAIL_*` — параметры отправки почты;
* `CELERY_BROKER_URL`, `CELERY_RESULT_BACKEND` — адреса Redis;
* `TELEGRAM_BOT_TOKEN` — токен бота, полученный у `@BotFather`;
* `TELEGRAM_POLL_TIMEOUT` — время ожидания обновлений Telegram;
* `OPENROUTER_API_KEY` — API-ключ OpenRouter;
* `OPENROUTER_MODEL` — используемая модель OpenRouter.

Файл `.env` содержит секреты и не должен попадать в Git. Не публикуйте
`SECRET_KEY`, пароль базы данных, почтовый пароль, Telegram-токен и ключ
OpenRouter в README, workflow или логах.

# Локальный запуск через Docker Compose

Для запуска потребуются Git, Docker и Docker Compose.

```
git clone https://github.com/DanilaSpasov/Library_API.git
cd Library_API
cp .env_example .env
mkdir -p staticfiles
```

Заполните `.env`, затем запустите сервисы:

```
docker compose up -d --build
docker compose ps
```

Docker Compose создаёт пять сервисов:

* `db` — PostgreSQL;
* `redis` — Redis;
* `web` — миграции, сбор статических файлов, Django и Gunicorn;
* `celery_worker` — обработка фоновых email-уведомлений;
* `telegram_bot` — получение и обработка сообщений Telegram.

PostgreSQL и Redis доступны только внутри Docker-сети. Gunicorn опубликован на
локальном адресе `127.0.0.1:8000`.

Остановить контейнеры без удаления данных:

```
docker compose down
```

PostgreSQL и Redis сохраняют данные в Docker volumes. Команда
`docker compose down -v` удаляет volumes вместе с базой данных и не должна
использоваться при обычной остановке.

## Локальный запуск через Poetry

Для такого запуска PostgreSQL и Redis должны быть установлены и запущены
отдельно. В `.env` укажите локальные адреса:

```
DATABASE_HOST=localhost
CELERY_BROKER_URL=redis://localhost:6379/0
CELERY_RESULT_BACKEND=redis://localhost:6379/1
```

Установите зависимости, выполните миграции и запустите процессы в отдельных
терминалах:

```
poetry install
poetry run python manage.py migrate
poetry run python manage.py runserver
poetry run celery -A config worker --loglevel=info
poetry run python manage.py run_telegram_bot
```

# Демонстрационные данные

Команда создаёт каталог из 100 книг и трёх физических экземпляров каждой книги:

```
docker compose exec web poetry run python manage.py seed_demo_library
```

При локальном запуске через Poetry:

```
poetry run python manage.py seed_demo_library
```

Перед загрузкой команда удаляет только старые библиотечные данные: подписки,
выдачи, экземпляры, книги, авторов и жанры. Пользователи не удаляются.

Метаданные основаны на открытом наборе `Goodbooks-10k`, опубликованном по
лицензии `CC BY-SA 4.0`.
Названия, авторы, жанры и описания адаптированы для русскоязычного каталога.

# Основные эндпоинты

## Аутентификация

* `POST /api/auth/register/` — регистрация читателя;
* `GET /api/auth/verify-email/{uidb64}/{token}/` — подтверждение email;
* `POST /api/auth/token/` — получение `access` и `refresh` JWT-токенов;
* `POST /api/auth/token/refresh/` — обновление `access`-токена;
* `POST /api/auth/telegram/connection-code/` — получение одноразового кода
  привязки Telegram.

Для защищённых запросов передайте access-токен:

```
Authorization: Bearer <access-токен>
```

## Каталог

* `/api/catalog/authors/` — список, просмотр, создание и изменение авторов;
* `/api/catalog/genres/` — список, просмотр, создание и изменение жанров;
* `/api/catalog/books/` — список, просмотр, создание и изменение книг;
* `/api/catalog/book-copies/` — управление физическими экземплярами.

Примеры параметров каталога:

```
/api/catalog/books/?search=Толстой
/api/catalog/books/?author=1&genre=2&is_available=true
/api/catalog/books/?ordering=-publication_year&page=2&page_size=20
```

## Выдачи и подписки

* `GET /api/loans/` — список выдач с учётом роли пользователя;
* `POST /api/loans/issue/` — выдача экземпляра читателю;
* `POST /api/loans/return/` — возврат экземпляра;
* `GET /api/subscriptions/` — активные подписки читателя;
* `POST /api/subscriptions/` — подписка на недоступную книгу;
* `DELETE /api/subscriptions/{id}/` — удаление собственной подписки.

Полные поля запросов, параметры и ответы представлены в Swagger UI.

# Развёртывание на сервере

1. Подключитесь к Ubuntu-серверу по SSH.
2. Установите Git, Docker, Docker Compose и Nginx.
3. Клонируйте ветку `develop` и перейдите в папку проекта.
4. Скопируйте `.env_example` в `.env` и заполните переменные окружения.
5. Запустите проект командой `docker compose up -d --build`.
6. Настройте Nginx на перенаправление запросов к `127.0.0.1:8000`.
7. Проверьте Swagger по адресу `http://<SERVER_IP>/api/docs/`.

GitHub Actions проверяет форматирование, тесты и сборку Docker-образа. После
добавления секретов `SSH_KEY`, `SERVER_IP` и `SSH_USER` изменения из ветки
`develop` автоматически загружаются на сервер.
